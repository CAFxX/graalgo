## 1. Observed failure (evidence)

- Captured wire (`hidden_files/red-master-watch/r3-logs/divide-wire.json`,
  program `14_goroutines_sum`): funcdecl `__ss_ReadRune` (`/funcs/2237`)
  contains exactly one invalid node —
  `assign{lhs:[r,size,err], rhs:[ifacemethod(method=ReadRune)]}`,
  i.e. **3 lhs / 1 rhs**. Verified by direct subtree walk
  (`assign nodes with single ifacemethod rhs in __ss_ReadRune: [(3, 'ReadRune')]`).
- The JVM leg dies in v1 `NodeFactory.buildAssign`
  (`internal/backend/truffle/src/main/java/graalgo/frontend/NodeFactory.java:4525`):
  throws `assign.fields: lhs/rhs length mismatch` unless
  `lhs.size()==rhs.size()` or the 2-var comma-ok shape. The gc leg passes;
  the backend builds every func in the wire JSON, so one dead synthetic
  helper poisons any program whose transitive closure includes it
  (fmt is in virtually every closure).

## 2. Root cause (traced, file:line)

1. `__ss_ReadRune` is generated by `transformMRFunc`
   (`internal/frontend/mr_disk.go:692-706`) from the DISK package `fmt`
   (go1.27.1 `src/fmt/scan.go:183-199`, `func (s *ss) ReadRune()`).
   Helper name = `__<recvType>_<method>` = `__ss_ReadRune`; pair type
   `__ss_ReadRunePair{f1,f2,f3}` (disk pair naming, f1..fN).
2. The helper body is the original body with returns rewritten
   (`rewriteMRReturns`). Unchanged line 189:
   `r, size, err = s.rs.ReadRune()`, where `s.rs` is `io.RuneReader`.
   Synthetic overlay wins over GOROOT (`resolveDiskPackageDir`,
   `internal/frontend/diskimport.go:137-141`), so this is the
   SYNTHETIC `io.RuneReader` — an interface-typed receiver.
3. `exportAssign` (`internal/frontend/export.go:7563`) tries
   `exportMultiResultDesugar` first. `classifyMultiResultCall`
   (`internal/frontend/mrdesugar_m5.go:1518`) reaches the interface-only
   arm (`mrdesugar_m5.go:1849`) which tries, in order:
   - `classifyIfaceMultiResultCall` — whitelist `m8IfaceMultiResultMethods`
     (`mrdesugar_m5.go:1273`): **no `ReadRune` entry** → nil;
   - `classifyDiskIfaceMultiResultCall` (`mr_disk.go:2151`):
     `lookupDiskMR("io","ReadRune","RuneReader")` → nil (interface-declared
     methods have no FuncDecl, so no disk-MR spec) → nil.
   
   The P4 general classifier `classifyUserIfaceMultiResultCall`
   (`mrdesugar_m5.go:2729` — synthesizes `__wsd_ifacepair_<Method>` on
   first use, cached in `userIfaceMRPairs`) is **not consulted here**.
4. It IS consulted at the expression-emission site
   (`exportIfaceMethodCall`, `export.go:10729` and `:10840`), so the
   `ifacemethod` wire node itself gets a valid pair type — but the
   STATEMENT exporter never desugars the call into temp+extraction.
5. `classifyMultiResultCall` returns nil →
   `exportMultiResultDesugar` returns `(nil,false,nil)` →
   `exportAssign` emits the raw `assign` node (3 lhs / 1 rhs) → invalid wire.

In short: **the statement-position multi-result classifier was left behind
when the P4 general-interface fallback was added to the expression-position
emitter. Expression and statement classification disagree on the same call.**
This is NOT the `56a3dd68` case (defer/go statement positions — different
position, already fixed); it is a new missing case in the same family.

## 3. Fix plan (general, no bridges, no name special-casing)

One routing change in `classifyMultiResultCall`'s interface-only arm
(`internal/frontend/mrdesugar_m5.go`, after the
`classifyDiskIfaceMultiResultCall` block, ~line 1858):

```go
// P4 (WS D, general interface MR): unlisted interfaces with
// multi-result methods (e.g. io.RuneReader.ReadRune). Mirrors the
// expression-position fallback in exportIfaceMethodCall: synthesize
// the interface pair on first use; the itab dispatches to the
// concrete type's pair-returning __-helper.
if plan := e.classifyUserIfaceMultiResultCall(selection); plan != nil {
        return plan
}
```

Why this is sufficient and correct:

- `exportMultiResultDesugar` (`mrdesugar_m5.go:3061`) arity gate:
  `want := len(plan.pairFields)` = 3 for ReadRune; `r,size,err = …`
  has 3 lhs → desugar proceeds.
- `desugarIfaceMultiResult` (`mrdesugar_m5.go:3795`) is kind-generic
  (`mrIfaceMethod`): re-emits via `exportIfaceMethodCall` (same cached
  plan from `userIfaceMRPairs`), declares `__p5mr_N` temp of the
  interface pair type (`vardecl`, 1 obj / 1 value — valid), then emits
  N single-target `assign`s via `desugarExtract` — all valid wire.
- Runtime dispatch: `multiResultHelperFor("fmt","ReadRune","ss")`
  (`mrdesugar_m5.go:2833`) → `lookupDiskMR` finds the spec →
  itab maps `io.RuneReader.ReadRune` on `*ss` to `__ss_ReadRune`.
  `multiResultHelperFunc` already guarantees positional TYPE identity
  between helper pair and method results (fails closed otherwise).
- Extraction is positional: `synthPairField` emits
  `selector{field, selpath:[i]}` (`mrdesugar_m5.go:4012`); the Java
  backend `buildSelector` (`NodeFactory.java:6028`) selects by
  `selpath` index, ignoring the name. So the synthetic-interface
  f0/f1/f2 vs disk-helper f1/f2/f3 naming difference is harmless.
- Both `=` (`exportAssign`, export.go:7563) and `:=` (`exportDefine`,
  export.go:7414) route through `exportMultiResultDesugar` →
  `classifyMultiResultCall`, so one change covers both (this also
  covers the review's `ch, size, err := r.ReadRune()` reproducer).
- It also covers `rewriteMRReturns`' general fallback
  (`__mr_t1..N := <call>` in `mr_disk.go:1952`), which re-exports
  through `exportDefine`.

Explicitly out of scope (pre-existing, deliberately loud, documented
re-test triggers): `var x,y,z = iface.MR()` ValueSpec position
(`export.go:7351` fail-fast); bare-statement/defer/go positions
(already handled); user-function 3-result calls (`userMRFuncs`
pair-transform, separate machinery).

     (3-result, e.g. a local `RuneReader`-shaped interface) called in
