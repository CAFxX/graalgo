## New P1 findings — blocks progress

### N-01 — Runtime + interop Java unit suites are not in per-push CI; only the truffle smoke-test runs — P1
- **Files:** `Makefile:155-156` (`test-ci: build` runs only `$(MAKE) -C internal/backend/truffle smoke-test`), `Makefile:241-244` (`test` runs truffle + runtime + interop suites), `.github/workflows/ci.yml:34` (`build-and-check`, runs `make all` on push/PR), `ci.yml:95-97` (`full-suite` job, `if: github.event_name == 'schedule' || github.event_name == 'workflow_dispatch'`), `internal/backend/runtime/Makefile:99-106` (`test` runs `SchedTestRunner`), `internal/backend/interop/Makefile:79-80` (`test` runs `IfaceTestRunner`).
- **What:** per-push CI (`make all` → `test-ci`) executes exactly two smoke fixtures (`Smoke`, `DslSmoke` — `internal/backend/truffle/Makefile:108-110`). The runtime suite (`SchedTestRunner`, 234 tests per the B-02 commit message, including the 7 new `LauncherOsArgsTest` tests guarding the B-02 fix) and the interop suite (`IfaceTestRunner`) run only under `make test`, which CI executes only in the `full-suite` job — weekly (Monday 04:00 cron) or manual dispatch. The other workflows (`conformance.yml`, `stdlib-gate.yml`, `fuzz-soak.yml`) run neither suite (verified by grep). So a regression in the runtime or interop module — including a regression of the B-02 fix itself — does not fail per-push CI; it is caught at most weekly. The B-02 commit message's own aside ("Interop suite not run: interop/out has no prebuilt test-classes") is a symptom of the same gap: the lane could not easily run the suite, and CI does not either.
- **Why P1, not P2:** the per-push done-gate ("push only after `make all` is green", `graalgo/AGENTS.md` §1) is hollow for the two modules that hold the runtime and the interop layer. Same severity class as R-10 (tool suites never run), which this review's predecessor filed as P1.
- **Suggested fix:** extend `test-ci` (or add a per-push CI job) to run `make -C internal/backend/runtime test` and `make -C internal/backend/interop test`. Measure the wall time first: if the suites are too slow for per-push, split them explicitly (fast subset per-push, full suite weekly) and record the split — do not leave the weekly-only arrangement undocumented. Verify by pushing a scratch change that breaks one runtime test and confirming per-push CI goes red (or by running the wired target locally under backoff-gated conditions).
- **Lane:** N-01 (this run). No prior lane covers this: registry grep for `test-ci`/`SchedTestRunner`/per-push-CI finds only red-master fix lanes (unrelated) and `rev1107-r10` (done — that one wired *Go tool* suites via `make test-tools`, a different scope).
