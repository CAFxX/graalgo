### R20-F01 — `runtime.*` interception discriminates on package NAME, not PATH (same class as R-1107-03, wider surface) — P1
- **Files:** `internal/frontend/export.go:8564` (Goexit guard), `:8585` (whole `runtime.*` block: `SetFinalizer`/`KeepAlive`/`GC`, `NumCPU`, `GOMAXPROCS`, `NumGoroutine`, `Gosched`, `ReadMemStats`, `GOROOT`, `Version`, `Stack`, `Callers`, `CallersFrames`, `FuncForPC`, `Caller`), `:6914` (`isGoschedCall`, same check for defer/go positions).
- **What:** all three sites gate on `obj.Pkg().Name() == "runtime"` (with an outer `pkgIdent.Name == "runtime"` spelling pre-filter). The codebase's own convention everywhere else is path-based: `sync/atomic` at `export.go:8519`, `reflect` at `:11199`/`:11229`, `runtimeStackMethod` at `:639` (`Pkg().Path() != "runtime"`), `isTimeIntrinsicFunc` in `synth_machinery.go:2194`. The R2-P2-9 comment at `:8558-8561` even blesses the `Name()` check as "the second gate" — it is not a gate at all against a same-named package. Verified by the reviewer reading the code this run; no REVIEW-14/18 coverage (grep for the line numbers, `isGoschedCall`, `GOMAXPROCS`, `NumCPU` finds nothing there).
- **Why:** any package whose *name* is `runtime` but whose path is not stdlib `runtime` (e.g. `import runtime "example.com/x"` or a third-party `…/runtime` package), defining one of those common names (`Version`, `Caller`, `GOMAXPROCS`, …), gets hijacked into graalgo wire nodes — or a spurious scope error (`runtime.Caller` multi-result error, Goexit "did not resolve to the overlay package") for valid Go code.
- **Suggested fix:** compare `obj.Pkg().Path() == "runtime"` at all three sites, matching the atomic/reflect precedent; add a regression test with an aliased non-stdlib `runtime` package defining `Version`/`NumCPU`.
- **Lane:** R20-F01.

### R20-F03 — Disk import silently selects the highest cached module version; go.mod pins are never read — P1
- **Files:** `internal/frontend/diskimport.go:139-225` (`resolveDiskPackageDir`, best-version loop at `:169-176`: `compareSemver(ver, best) > 0`); verified by grep: no `go.mod`/`require` reading anywhere in `internal/frontend/` or `cmd/graalgo/` (the p3frontend loader's `findModule` reads go.mod only for the module *path*).
- **What:** a third-party import resolves to `$GOMODCACHE/<path>@<highest version>`, regardless of what the importing program's go.mod pins. A program pinning `v1.3.0` with `v1.6.0` also in the cache silently compiles against v1.6.0. Verified by the reviewer reading the code this run; no REVIEW-14/18 coverage.
- **Why:** silent wrong-version selection vs gc — behavior divergence or spurious compile errors with no diagnostic pointing at the version. The comment "The probe harness pins the cache to the intended version" only covers harness runs.
- **Suggested fix:** needs design — resolve the version from the importing module's go.mod `require` directives (MVS over the module graph), or fail loudly when the required version is absent from the cache instead of silently taking the newest.
- **Lane:** R20-F03.

### R20-F04 — `graalgo run/build/vet/fmt <import-path>` fails: import paths are never resolved — P1
- **Files:** `cmd/graalgo/main.go:239-280` (`resolveFiles`); `commands.go:92,200,259,293` (all four commands funnel through it).
- **What:** `resolveFiles` does `os.Stat` on each argument; an import path errors with `no such file or directory: <path>`. Yet the usage strings advertise `[packages]` (`main.go:108,122`, `build`/`test`/`vet`), and `go run`/`go build` accept import paths. Only filesystem paths and directories work. Zero tests cover `resolveFiles` or any import-path argument. Verified by the reviewer reading the code this run. Distinct from REVIEW-18 FE-09 (which is build-excluded files inside a directory expansion, a different mechanism in the same function).
- **Why:** a documented, advertised invocation form fails outright — blocks the drop-in replacement claim for the most common multi-package workflow.
- **Suggested fix:** needs design — resolve import paths to package directories (module lookup / `go list` equivalent) in `resolveFiles`; add tests for import-path, directory, and `.go`-file args across all four commands.
- **Lane:** R20-F04.

### R20-T01 — diffharness typeparam/srctest runs accept zero comparisons as PASS (live CI gates can go green having compared nothing) — P1
- **Files:** `test/differential/cmd/diffharness/main.go:451-517` (`cmdTypeparamRun`), `:567-636` (`cmdSrctestRun`); `test/differential/internal/typeparam/typeparam.go:276-332` (`Run`), `:71-91` (`Scan`), `test/differential/internal/srctest/srctest.go:70+` (`Scan`).
- **What:** `typeparam.Run` returns `([], nil)` when `included` is empty (all files excluded), and both `Scan` functions return `([], nil)` for a directory with zero `.go` files (only a `ReadDir` error fails). Both commands then print `"typeparam/srctest run: 0 comparisons, 0 diverged"` and return nil → exit 0, after which `run_conformance.sh` prints `"CONFORMANCE GREEN"`. So a wrong `GOROOT_TEST` pointing at a directory with no top-level `.go` files, or an exclusions file covering every program, passes the Layer-2 conformance gate silently. Verified by the reviewer reading all four functions this run. **Scope note:** the `run` leg of this hole is already filed as REVIEW-18 TL-03 (`loadCorpus`/`cmdRun`) — this finding files only the two unfiled legs (typeparam, srctest). **Correction to the survey lane:** its snapshot-check leg is WRONG for the normal case — REVIEW-18 TL-03 is right that `snapshot check` fails loudly on an empty kept set (its recorded-missing loop errors when corpus programs have no recorded snapshot, and `loadSnapshotDeps` → `DiscoverCorpus` errors on an empty corpus dir). The only remaining snapshot hole is second-order: a snapshot *recorded* with zero programs + matching exclusions would check green — folded into this lane as a `snapshot record` guard (error when recording zero programs), not as a check-leg defect.
- **Why:** same failure class as R-02 (zero tests → PASS), but in the *live* Layer-2 conformance gate (per-commit on frontend changes) — the gate whose entire purpose is comparing programs.
- **Suggested fix:** require a non-zero comparison count in both commands (return an error when `len(comps) == 0`); error in `snapshot record` when zero programs would be recorded. Add a unit test pinning the empty-kept-set case (no test currently covers it; `corpus_test.go:19` only pins the empty-dir discovery error).
- **Lane:** R20-T01.
