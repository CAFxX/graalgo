## New P1 — blocks progress

### RV13-01 — TLS server handshake sleeps 10s on the real Handshake path — P1
- **Files:** `internal/frontend/synth_crypto_tls.go:750`, inside `func (c *Conn) Handshake() error` (:723); comment :743-749, TODO :749.
- **What:** after `verifyPeer()` succeeds, a server-side `Handshake()` executes `time.Sleep(10 * time.Second)` "so the client's prints land first (byte-identical differential)". This is the synthetic `crypto/tls` `Conn.Handshake` — shipped stdlib surface, not test-only code: every server-side TLS handshake costs +10s wall-clock. Timing-based ordering is racy by construction (a client slower than 10s still flips the order; a faster one still waits the full 10s), so the sleep buys neither correctness nor reliability.
- **Why P1, not P0:** output is correct, only late; but it is a real behavioral defect in shipped stdlib — it makes the wave3 TLS corpus slow and flaky and any server-TLS program 10s slower per handshake. (The morning review noted this as an out-of-scope observation and did not file it; it is filed here.)
- **Suggested fix:** gate the sleep behind a test-only signal (env var / build tag) so production handshakes never sleep; the proper fix, per the TODO, is real synchronization between the test's client/server goroutines. Note the sibling 1ms sleep at :790 is a bounded poll-yield in the `NEED_WRAP` transitional state — legitimate, leave it.
- **Lane:** RV13-01.

- **Files:** `cmd/graalgo/testsynth.go:258-274` (`toString`), used by `sprintf` (:230) and `joinArgs` (:219).
