## 1. Verdict — skip-list growth assessment (SPEC §3.6)

| metric | P3-M6 | M10 | Δ |

| live skip-list (new in v1.1.0) | — | **118** | — |

**No escalation.** SPEC §3.6's kill trigger is skip-list growth > 15;
the skip list *shrank* by 54. Growth decomposition (target-level diff of
the two skip lists):

- **16 targets resolved by real provision** — the intrinsic registry
  (`internal/poll.runtime_poll*`, 8) and new synthetic packages
  (`syscall.*` 6, `internal/bytealg.MakeNoZero`,
  `net/http.(*Transport).RoundTrip`).
- **39 targets resolved by methodology correction** — v1.0.0 counted the
  single-field `//go:linkname name` form as needs; they are provisions
  (the target *is* the declared symbol). v1.1.0 marks live ones
  SATISFIED (48 such satisfactions in the new report; 39 of them were on
  the P3-M6 skip list).
- **1 newly missing target**: `graalgo.http.client.do` — the only genuine
  regression-shaped finding (see Tier A below).
- Net: −54. Even excluding the 39 methodology corrections, the real
  movement is −15 — far from the +15 trigger under any reading.

Of the 471 skip-list targets, only **118 are live** — referenced by code
graalgo actually compiles (non-shadowed stdlib files + synthetic sources).
The other 353 are referenced solely by real-stdlib files superseded by a
synthetic package (e.g. real `os`, `reflect`, `net/http`); they are not
compiled and need no action. The work list below is built from the 118.

Reachability triage (beyond live/shadowed): a "live" file is still only
*compiled* if something imports its package. No synthetic source imports
`internal/*`, `runtime/cgo`, `runtime/pprof`, `runtime/trace`,
`runtime/debug`, or `plugin`, and user imports of `internal/*` are not
admitted — so those references are conditional on program decisions
(Tier B) or dead (Tier C). Only Tier A is referenced by a synthetic
source that ships today.

Effort rubric: **S** = hours, **M** = days, **L** = weeks,
**XL** = program-level (weeks–months).

## 2. Tier A — implement now (1 target)

### A1. `graalgo.http.client.do` — wire the existing intrinsic (S)

- **Needing package:** synthetic `net/http` (`Transport.RoundTrip`
  delegates to it).
- **What it is:** the linkname the synthetic net/http client uses to reach
  `GoHttp.clientDo` (java.net.http.HttpClient delegation, P3-M9 tier-5).
  `GoHttp.clientDo` is implemented and documented in
  [GoHttp.java](../../internal/backend/interop/src/main/java/graalgo/p3net/GoHttp.java),
  but **never registered** — `Linknames.register` is called only from
  [LinknameIntrinsics.java](../../internal/backend/interop/src/main/java/graalgo/p3link/LinknameIntrinsics.java),
  which has no `graalgo.http.*` table.
- **Implementing it entails:** adding a `registerHttpIntrinsics()` block
  to `LinknameIntrinsics.install()` following the existing tables, e.g.
  `Linknames.register("graalgo.http.client.do", args ->
  GoHttp.clientDo(args[0], args[1], args[2], args[3]), 4)` with the D5
  argument adaptation the file documents per target (strings arrive as
  GoString, body as GoSlice; returns the documented Object[] triple).
  Then a link test: synthetic net/http `Transport.RoundTrip` against a
  local test server.
- **If not done:** any program importing `net/http` that performs a client
  request fails at program-build link time.

## 3. Tier B — program decisions (72 targets)

These become real needs only if the corresponding capability becomes
importable/supported. Each is one coherent work item, not 72 independent
linknames.

### B1. cgo support — 59 targets (XL)

Targets: the 44 `cgo.*` bridge symbols (`_cgo_*`/`x_cgo_*` pairs: thread
creation, pthread keys, mmap/munmap, libc setuid/setgid/seteuid/setegid/
setreuid/setregid/setresuid/setresgid/setgroups, sigaction, traceback and
caller symbolization, thread start/yield, `_cgo_panic`,
`_crosscall2_ptr`, env init), the 9 `syscall.cgo_libc_*` (same libc
functions via the synthetic `syscall` package, from `runtime/cgo/linux.go`),
and `runtime._cgo_clearenv`, `runtime._cgo_panic_internal`,
`runtime._cgo_setenv`, `runtime._cgo_unsetenv`, `runtime.iscgo`,
`runtime.set_crosscall2` (from `runtime/cgo/*`).

- **Needing package:** `runtime/cgo` (real stdlib, compiled only for cgo builds).
- **Implementing it entails:** a cgo FFI on Truffle/JVM — C calling
  conventions, Go↔C callback trampolines (`crosscall2`), thread-state and
  signal-handler bridging. The linknames are the runtime↔libc surface of
  that project, not an incremental list.
- **Gated on:** program decision "support cgo". Until then, no action.

### B2. Observability (pprof/trace/debug) — 12 targets (L)

Targets: `runtime.pprof_blockProfileInternal`,
`runtime.pprof_fpunwindExpand`,
`runtime.pprof_goroutineLeakProfileWithLabels`,
`runtime.pprof_goroutineProfileWithLabels`,
`runtime.pprof_makeProfStack`, `runtime.pprof_memProfileInternal`,
`runtime.pprof_mutexProfileInternal`,
`runtime.pprof_threadCreateInternal` (from `runtime/pprof`),
`runtime/pprof.runtime_cyclesPerSecond`, `runtime.traceAdvance`,
`runtime.traceClockNow` (from `runtime/trace`), `runtime.setCrashFD`
(from `runtime/debug`).

- **Needing packages:** `runtime/pprof`, `runtime/trace`, `runtime/debug`
  (real stdlib; currently scope errors via the overlay — not importable).
- **Implementing it entails:** first making those packages importable, then
  one intrinsic per target backed by JVM-side data sources (thread dumps
  for goroutine profiles, allocation sampling for mem profiles, a
  monotonic clock for the trace clock). The linknames are the smaller part;
  the data sources are the work.
- **Gated on:** program decision "support profiling/tracing".

### B3. Plugin support — 1 target (XL)

Target: `runtime.doInit` (from `plugin/plugin_dlopen.go`).

- **Implementing it entails:** dynamic Go plugin loading on Truffle —
  program-level decision, out of proportion to a single linkname.
- **Gated on:** program decision "support plugins".

## 6. Tool changes (v1.0.0 → v1.1.0)

`tools/stdlib-linkdiff` was stale relative to the tree (its provided-set
extraction covered only the P3-M6 surface; its tests failed on the
current tree). Changes, all mechanical:

- **Provided set**: added source 5 — every embedded synthetic package in
  the `syntheticSources` registry
  ([internal/frontend/synth_machinery.go](../../internal/frontend/synth_machinery.go)), resolved through const
  fragments/`+` chains/parenthesized concatenations and parsed with
  go/parser; symbols qualified by import path. 241 → 5,772 symbols.
  Unparseable sources are recorded on `synthetic_parse_errors`, never
  silently dropped.
- **Need set**: the synthetic sources' own `//go:linkname` directives are
  now scanned (140 directives — the exporter's linkname scan covers them,
  so they are real needs).
- **Shadow marking**: vendored-tree entries whose import path the overlay
  substitutes (`overlayImporter.Import` switch in
  [internal/frontend/export.go](../../reviews/phase1-m5-loopcap/snapshot/export.go), 137 paths) are marked `shadowed_by`;
  the report splits `skip_list_size` (comparable across releases) from
  `live_skip_list_size` (actionable subset).
- **Self-links**: the single-field `//go:linkname name` form is a
  provision, not a need — live ones classify SATISFIED (was: MISSING).
- **Local-name rule**: corrected to gc's actual rule (verified empirically
  against the gc toolchain): the local name must match *a* declared
  function/variable in the package, not necessarily the declaration the
  comment attaches to (the `runtime/cgo` x_/_ pair pattern). The old
  "gc rejects this" reason was factually wrong for that pattern.
- Tests: 8 new tests (registry resolution, shadow set, parse-error
  surfacing, shadow marking, synthetic directive scan, package-scope
  local names, self-links, live split); the `graalgo.*` lowercase
  intrinsic namespaces exempted from the unexported-symbol check by
  provenance.
