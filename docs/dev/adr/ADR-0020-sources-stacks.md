# ADR-0020 — Source sections, program counters and tracebacks from Truffle frames

**Date:** 2026-11-25
**Status:** accepted (lane tr-sources, WP-TR-AUDIT-6 of
[truffle-audit.md](../../arch/truffle-audit.md); finding F-12.1; closes
[BUG-0047](../bugs.md))
**Scope:** the new path: `graalgo.go.nodes` (`N.Stmt`, `N.CallRef`,
`Calls.Body`, the roots), `graalgo.go.runtime` (`Positions`, `Stacks`,
`GoProcess`), `graalgo.go.build.NodeFactory`, `graalgo.go.loader.Program`,
the runtime facade ([stdlib/fork/runtime](../../../stdlib/fork/runtime/)) and
the intrinsic registry. Playbook §1.9, §4, §5, §12.

## Context

The new node package had no `SourceSection`, tag, qualified name or stack
walk: every Truffle tool printed `(Unknown)`, `runtime.Caller` answered
`ok == false`, `runtime.Callers` no frames (BUG-0047: reflect's panics that
name their method, `log`'s `Lshortfile`), and a fatal panic printed only the
goroutine header. GIR already carried what gc reports: every statement and
expression has a 1-based index into its function body's position table
(file, line delta, column, length; a call at its `(` token, the token gc
attributes the call to).

## Decision

1. **Positions stay in GIR's table; nodes keep an index.** `N.Stmt` and the
   call nodes (`N.CallRef`: `Call`, `CallClosure`, `IfaceCall`) carry a
   `@CompilationFinal int pos` set by the factory before adoption (a
   statement gets its GIR statement's position unless a nested statement
   already gave it one; blocks and labels have none). A function's
   `Positions` (gc name, wrapper flag, lazily decoded table) is shared by the
   root, its split copies and its range-over-func bodies; `getSourceSection()`
   builds a section on demand. No `SourceSection` object per node (H21).
2. **One character-less `Source` per Go file name and program**
   (`Source.CONTENT_NONE`, line/column sections; nothing reads the file, which
   may not exist where the program runs). gc's `<autogenerated>`-style names
   are internal sources; generated wrappers (`FuncLit.wrapper`) are internal
   roots.
3. **Root names are gc's**: `pkg.F`, `pkg.(*T).M`, `pkg.T.M`, `pkg.F[...]`,
   `pkg.(*T[...]).M`, `pkg.f.func1`, `pkg.f.func1.func1`, `pkg.f-range1`
   (`getName` = `getQualifiedName`); a root's section is its declaration line.
4. **Tags**: `StatementTag` on positioned statements, `RootTag` and
   `RootBodyTag` on `Calls.Body` (the function body, also the `return`
   target), `CallTag` on positioned calls. Wrappers come from
   `@GenerateWrapper` on `N.Stmt` and `N.Ref` (every call is a boxed `Ref`) and
   exist only while an instrument is attached. No `ExpressionTag` or variable
   tags yet: the typed carrier families (`I64`, `F64`, `Bool`) would each need
   a wrapper and expression positions; deferred to the debugger work (scopes).
5. **Stacks are Truffle frames.** A Go frame is a frame of a root
   implementing `Positions.Root` that is not a wrapper (intrinsics and thunks
   are not Go frames). Its position is the nearest positioned node at or above
   the frame's call node (for the panicking frame: the exception's location).
   `runtime.callers` walks `iterateFrames`; a fatal panic's frames come from
   `TruffleStackTrace` of its `GoPanic` (already an `AbstractTruffleException`
   with an unlimited, lazily captured trace — no new cost on the panic path).
   All of it runs behind `@TruffleBoundary`.
6. **Program counters** (per process, `Stacks`):
   `0x400000 + (id << 20) + (pos << 2)`, `id` numbering functions by gc name
   as they first appear in a stack, position 0 the entry. `Callers` reports
   return pcs (call pc + 1), which decode to the same position, so gc's
   `pc - 1` rule in `CallersFrames` holds. The range lies below the
   `uintptr` handle range (`Handles.FIRST`), so `FuncForPC` also resolves a
   func value's handle (`internal/abi.FuncPCABI0`, `reflect.Value.Pointer`).
7. **The facade is Go over four intrinsics** (`runtime.callers`, `funcInfo`,
   `pcFileLine`, `Stack`; registry version 2): `Caller`, `Callers`,
   `CallersFrames`/`Frames.Next`, `FuncForPC`, `Func.Name/Entry/FileLine` are
   upstream's logic.
8. **Traceback format** is gc's: `pkg.f(...)` (no argument words: gc's form
   for an inlined frame), a tab, `file:line +0x<pos offset>`; `runtime.*`
   frames elided; at most 100 frames, then gc's
   `...additional frames elided...`. The differential oracle is
   [tbnorm.py](../../../test/m1a/tbnorm.py) (names and file:line compared).

## Alternatives rejected

- **A shadow stack** pushed on every call (v1's `GoStackFrame`, H3): a cost on
  every call for a rare query; Truffle reconstructs inlined frames for free.
- **A `SourceSection` per node** (v1, H21): 8 bytes per node, sections only
  where the factory remembered.
- **Reading the file** (`Env.getPublicTruffleFile`): sections would carry
  text, but the file may be gone and tools only need lines; can be added
  behind the same `Positions` table.
- **truffle-design §6.5's `function << 24 | site` pc**: the same idea; the
  GIR position index replaces a separate call-site ordinal.

## Consequences

- `--cpusampler`, `--cputracer`, `--coverage` and polyglot
  `ExecutionListener`s show Go names and file:line
  ([test/m1r/tools.sh](../../../test/m1r/tools.sh), both goroutine modes);
  an uninstrumented tree is unchanged (one extra `Body` node per function).
- Not yet gc's (open, [traceback-normalization.md](../../arch/traceback-normalization.md)
  rules C2/T5): the boundary runtime frames (`runtime.main`,
  `runtime.goexit` at the bottom of `Callers`; `runtime.gopanic` — printed
  `panic(...)` — under a deferred call run by a panic, whose frames below are
  not the panic site's); a deferred call run at a normal return reports the
  deferring frame at its declaration line, gc at the closing brace or
  `return`; std file names keep gc's object-file form `$GOROOT/src/...` (the
  link-time GOROOT is not recorded); `runtime.Stack(buf, true)` reports only
  the caller's goroutine; no `created by` trailer.
- Revisit when the debugger work adds scopes (`NodeLibrary`) and expression
  positions, or if a profile shows the lazy table decode or the per-name pc
  map on a hot path (`log` with `Lshortfile` calls `Caller` per line).
