## Per-category rationale (summary; full rationale: ADR-0007)

1. **evaporate** (runtime-core): no Go stacks exist on Truffle, so stack/register/GC-ABI asm has no meaning. Go-visible services (fastrand, nanotime, memequal, ...) are provided by real graalgo intrinsics or the Linknames registry (ADR-0004 D1; P3-M4 audit: 259 REAL, 0 true stubs). Includes internal/cpu (host CPUID -- the host JVM owns CPU features; coupling note for the crypto emulate leg) and os/signal (the JVM owns signals).
2. **intrinsify** (atomics/bytealg): `graalgo.runtime.Atomics` is real (P3-M4 audit, 16 methods) and reachable from Go via the phase-3 AtomicOpNode; bytealg hot paths map to `Intrinsics.memequal` (real) + planned ByteAlg vector nodes, with the pure-Go `*_generic.go` fallback selectable by excluding the arch asm.
3. **emulate-then-intrinsify** (crypto): the emulate leg compiles the pure-Go generic implementation with arch asm excluded; the intrinsify leg (per-algorithm SIMD intrinsics) is a later phase -- re-test trigger recorded per file.
4. **jvm-math** (math): the JVM implements IEEE754 exactly (java.lang.StrictMath); math/big's asm kernels are speedups over mostly-Go code (T4), with java.math.BigInteger semantics as the reference.
5. **unsupported**: toolchain sources (cmd/), vendored modules (vendor/), and stdlib asm with no decided strategy yet (syscall trampolines, hash/crc32, reflect stubs, experimental simd). Each carries its re-test trigger (the bring-up wave that decides it). Encountering one is a build error, never silent.
