# P3-M3 `iface` corpus

Go programs exercising the P3-M3 interface dispatch (ADR-0003),
differential vs stock gc 1.27.1. The two P3-M3 halves (Go exporter ≥
0.4.0 emitting `ifacemethod` wire nodes; Java `IfaceDispatchNode` with
PIC-on-itab-identity) had never been tested end-to-end together; this
corpus is that integration test.

## Programs

| Program | Covers |
|---|---|
| `if00_basic_dispatch.go` | value-receiver and pointer-receiver types through one interface; concrete passed where the interface is expected |
| `if01_multi_writer.go` | io.Writer-shaped (single-result — see scope notes) with 3 implementations; Fprintf-style compose-then-write |
| `if02_sort_iface.go` | sort.Interface — `import "sort"` is out of scope, so the interface and the sort are inlined; bimorphic call sites |
| `if03_error_iface.go` | custom error types, `Error()` dispatch, nil error in interface |
| `if04_assert_iface.go` | empty-interface boxing, type assertion to a non-empty interface (single and comma-ok), then dispatch |
| `if05_megamorphic.go` | ONE call site fed 4 distinct concrete types → PIC (limit 3) overflows into the megamorphic hash fallback |
| `if06_nil_panic.go` | nil interface method call → panic, exit 2 |
| `if07_typed_nil.go` | typed nil (`(*Buf)(nil)`) in a Writer → method runs with nil receiver |
| `if08_embedded_promotion.go` | `struct{ *Buf }` satisfying Writer purely by promotion (receiver adaptation via the wire `index` path); value-embedding + value-receiver promotion |
| `if09_iface_embedding.go` | `interface{ Writer; Closer }` — flattened embedded method set |
| `if10_iface_param.go` | interface-typed parameters: concrete arg to a plain function (factory adaptation) and to an interface method (P3 builder replica) |

## Files per program

- `ifNN_*.go` — the program (deterministic: only aggregates on stdout).
- `ifNN_*.expected` — gc stdout (regenerated by `regen.sh`).
- `ifNN_*.panic` / `ifNN_*.panic.gc` — for `if06`: the expected first
  stderr line, graalgo leg / gc leg.

## Running

```bash
./regen.sh               # regenerate .expected/.panic.gc from gc 1.27.1
./run_differential.sh    # gc binary vs graalgo (P3SyncMain): stdout bytes,
                         # exit codes, first stderr line (panic programs)
```

The differential runner filters the known JVM `Unsafe` warnings on
stderr (harness noise, cf. `p3frontend/DESIGN.md` §7). Programs are
single-goroutine; one `--gmp=1` run each (the sync corpus's gmp sweep
covers the scheduler).

## Scope notes (frontend/v1 WS D, all verified by differential)

- Interface methods are single-result: `io.Writer`'s `(int, error)` is
  out of scope, so the corpus uses `Write([]byte) int`. The dispatch
  mechanics are identical.
- `import "sort"` is out of scope (the importer resolves only the
  synthetic `fmt`/`sync`/`runtime` overlays) — if02 inlines the
  interface and the sort.
- The synthetic `fmt` has the seven D4 symbols only (no `Fprintf`) —
  if01 composes `Sprintf` + `Write` directly. Calling a user-defined
  variadic function with packed arguments is out of scope.
- Method calls needing an implicit address-of/deref on the receiver are
  out of scope (if00/if08 are written to avoid them).
- Value-embedded field + pointer-receiver promoted method is rejected
  with a named P3-M3 scope error at itab build (silently type-unsound
  otherwise); if08 covers the supported promotion shapes.
- if06 panic rendering: the message is gc's exact
  `runtime error: invalid memory address or nil pointer dereference`
  with exit code 2, but the Phase-2 scheduler prints Go values via
  `toString`, so the line reads
  `panic: GoErrorValue{runtime error: ...}` (pre-existing P2 rendering;
  the Phase-1 launcher renders it gc-exact via `PanicRendering`).
  Recorded as a scoped divergence in `if06_nil_panic.panic`.
