# ADR-0001 — graalgo Phase-0 architecture decisions

**Date:** 2026-10-03
**Status:** accepted 2026-10-03 — coordinator-signed and program-owner-signed (Carlo: "sgtm"). Both Phase-0 peer reviews remediated and re-tested. SPEC acceptance (ID lock) remains the Phase-1 entry gate per below.
**Scope:** the five architectural forks Phase 0 was charged with deciding
(PHASES.md §2). Normative detail lives in `SPEC.md`; this record captures
*what was decided, what was rejected, and why*.

---

## D1. Language frontend: verbatim `go/*` vendoring (service)

**Decision:** the frontend is the stock Go release's own `go/parser` +
`go/types` (+ `gopls`-adjacent helpers where needed), re-vendored atomically
per release, fronted as a service the Truffle backend queries. No fork of
`cmd/compile` internals. `[DECIDED]` (SPEC §3.2, GG-0012).

**Rejected:** forking `cmd/compile` internals — same porting surface as
`go/*` with worse stability (SPEC §10.2 verdict-scope ledger); reimplementing
parsing/type-checking — unbounded semantic-drift risk against "always latest
Go".

**Consequence:** per-release frontend toil is bounded by the `go/*`
compatibility promise; a `-lang` gate pins the language version. Re-test
trigger: the `go/*` compatibility promise is withdrawn upstream.

## D2. Toolchain driver: wrap via `-toolexec`, no fork

**Decision:** ship the stock Go distribution with the compile backend swapped
behind the existing `-toolexec` seam. The `go` driver is never modified
(spike 5: 52/52 txtar scripts identical through the wrapper; the one
divergence, response-file handling, was fixed in the wrapper). Fork remains
only as a priced escape hatch. `[DECIDED]` (SPEC §3.1, GG-0011).

**Rejected:** reimplementing the `go` driver (~74k LOC estimate, T3) —
rejected in the verdict-scope ledger.

**Consequence:** `alias go=graalgo` inherits module/proxy/sumdb/build-cache
behavior verbatim. Kill trigger (PHASES.md §6): argv-interception gaps that
force the fork *and* whose merge burden breaks the toil bound.

## D3. Three execution modes, hybrid default (pending meta-gate)

**Decision:** one frontend, one value model, one runtime library; the modes
differ only in packaging: (a) JIT-only on HotSpot (dev loop), (b) AOT-only
Native Image (W^X / size-constrained), (c) AOT+JIT hybrid — application,
Truffle interpreter, and the Graal compiler itself AOT-compiled into one
binary, with the embedded JIT re-optimizing hot guest code at runtime (the
shipping Truffle-on-SubstrateVM mechanism). The AOT baseline must be correct
and performant without the runtime JIT. `[DECIDED]` procedure (SPEC §3.9,
GG-0006/GG-0049/GG-0050/GG-0060).

**Consequence:** the hybrid's meta-gate (GG-0049) decides whether (c) stays
the default: it must beat *both* single modes on ≥1 workload class or be cut.

## D4. OS scope: Linux-first

**Decision:** Linux-first (72 syscall files, epoll); darwin a moderate
deferral; Windows out of v1 (2–3× cost: IOCP + 6.7k-line syscall layer).
`runtime/cgo` + `plugin` stubbed as unsupported initially. `[DECIDED]`
(SPEC §3.8, GG-0023).

**Re-test trigger:** Linux green → re-measure Windows (SPEC §7.13,
verdict-scope ledger).

## D5. Concurrency: user-space scheduler over 1:1 virtual threads (option C)

**Decision:** goroutine = virtual thread + scheduler token. Loom's ForkJoinPool
is demoted to an untrusted thread pool (no scheduling discipline assumed —
spike 2 falsified FJP fairness: 0 vs 200,000 latency samples `[VERIFIED]`).
Scheduling discipline lives in user space: quantum-based preemption
(`Safepoint.poll()` at back-edges/function entries; indefinite
`LockSupport.park()` + resume token on expiry; 10ms default quantum),
a single platform-thread drainer (blocking take → admit → unpark; FIFO
`runFifo` + priority `wakeFifo`/`initFifo`), and an in-flight cap =
`GOMAXPROCS` enforced as a hard assert. All runtime/stdlib-adaptation
blocking goes through scheduler-aware primitives. `[DECIDED]` (SPEC §3.5;
GG-0017/GG-SCHED-0001–0004/GG-WAKE-0001–0003/GG-FAIR-0001–0003).

**Rejected:** (i) yield-to-FJP (spike 2 KILLED — systematic starvation);
(ii) interpreter-level M:N re-scope (viable but unvalidated; dominated by
option C on simplicity — no frame heapification — and option C is empirically
validated, spike 2b PASS: 11,824–15,603 vs 0 samples across runs, cap assert
never tripped, 48,140/48,140 wakeups, quiescence fairness max/mean 1.05).

**Residual risks (explicit, not hidden):** per-hop overhead mean 27–41µs
across runs on the contended 2-vCPU VM (2.7–4.1% at 1ms; scoped fix
**measured**: 29.9µs mean = 0.30% at 10ms, spike-2b rework battery);
unexplained 38µs cold-drainer wakeup on the 2-vCPU VM (suspected host wakeup
latency, hypothesis; re-test: server hardware); 17× absolute rate gap vs
stock Go is prototype hop cost plus a structural per-quantum cross-thread hop
production minimizes but cannot eliminate — no production perf claim until
the production-path re-measurement trigger fires *(amended 2026-10-03: was
13× from the superseded same-day draft; archived rework battery gives ~17× —
program-owner approved)*; blocking I/O uses the
slot-releasing NIO wrapper (P0-2 resolved; Phase-2 throughput-cost trigger
kept).

**Falsifier:** Phase-2 preemption-torture + pinning matrix re-run against this
design; kill trigger = systematic divergence the scheduler cannot close, **or**
any residual risk hardening into a mechanism blocker (overhead mean unfixable
by the 10ms quantum, cold-drainer latency unexplained at server scale,
slot-releasing NIO wrapper throughput cost unbounded) → re-scope (SPEC §8
row 2).
